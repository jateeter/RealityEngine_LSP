## Why this is a pointer

This repository implements the contract in Common Lisp; it does not define it.
The contract binds four runtimes and its §8 acceptance test is byte equivalence
across them, so the definition cannot live inside any one implementation.

The master carried no pointer here until now — the failure one step before
drift. Nothing in this repository named the contract, and the natural repair for
"the arbiter needs describing where it is implemented" is a local description
that quietly becomes a second master.

The risk is sharper for this runtime than for the others. §7's parallelism
directive for LSP proposes an actor-per-contended-cell decomposition, on the
grounds that mailbox accumulation is naturally commutative and so matches §4.1
directly. That is a design this repository would otherwise be tempted to write
down locally, in its own words, alongside the code that implements it — and a
second statement of a shared rule is how two correct edits end up describing the
same behaviour differently.

## What this repository owns

The Lisp implementation and its tests. `ARBITER_ARCHITECTURE.md` here is a
pointer for the same reason and to the same place; it separates the three
distinct things this system calls "arbitration" — `outputMergeTransformation`,
`arbiterRule`, and the cell arbitration registry.
